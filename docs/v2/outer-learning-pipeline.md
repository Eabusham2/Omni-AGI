# Actual outer learning orchestration

## Runtime path

`outer_learning_pipeline.py` consumes the current request-owned scheduler at
the real Worker learning entry points. A saved job, event, exported receipt,
or old controller session cannot create that runtime ownership. An unarmed
request follows its existing ordinary implementation without a new scheduling
receipt. Importing the module performs no neural work.

The concrete Worker entries now bind their actual request/job cancellation to
training, dataset ingestion, queued chat replay, action-result learning,
capability learning, tool-outcome learning, evolution proposal/evaluation/
promotion/rollback, checkpoint, and snapshot. The current request ID is checked
before using its cooperative flag; a different request cannot inherit that
flag. Evolution's existing isolated training and replay bodies receive this
same cancellation callback. No candidate is created for this source check.

Actual media objectives, replay objectives, latent rehearsal, slow candidate
training, evolution replay, and queued replay are entered through their real
brain methods. Mutable optimizer, recurrent, sensory, graph, source, and
lineage closures remain with their actual owners. These are fixed phases, not
new privately migratable work kinds. Nested fixed phases are timed visibly but
counted only once in the aggregate fixed duration. Isolated candidate owners
are distinguished by runtime object identity even when their saved brain ID
matches the parent. They do not inherit the parent's compute-route authority.

The prepared text-wave consumer remains the existing fully closed operation.
Its private comparisons still exclude source/cursor/checkpoint publication and
real world callbacks. Qualification is refused inside a pinned mutation or
world-effect barrier. At its true canonical execution boundary,
`owned_operation_choice` associates the exact current controller, prepared
identity, candidate, session, policy, and budget. `genuine_learning_operation`
consumes that live association and current candidate admission around the
existing genuine execution, complete state/report/RNG/effect equality checks,
and original-owner restoration. It never runs an update from a receipt or
repeats an update to obtain a summary.

Fixed owner phases flow through the same real prefix admission and complete-
operation selector as the existing thirteen operation kinds. Its conditional
cost is one already-observed fixed prefix plus matched complete-compute
observations, not a benchmark of a separately replayed whole pipeline. The
ordinary supported candidate remains the fallback. Actual selected execution
records its own admitted target/home resource observations; shared physical
groups retain the existing single-ceiling accounting.

## Stop and publication

Stop is checked before genuine compute and at existing safe learning boundaries;
slow waves/microbatches, media windows/steps and evolution replay steps now also
check the current learning callback. Real errors retain the existing rollback,
last-committed-generation recovery, source cursor, and replay idempotency rules.

An already-applied update must still reach its original atomic publication.
Checkpoint/cursor/promotion/rollback phase observation therefore adds no new
Stop gate or scheduler pressure-admission gate before that publication. The
original save, disk admission, checksum, immutable evaluation, permission and
transaction rules still run. `note_learning_commit` is called only after the
existing atomic generation callback has marked the commit durable, and counts
only inside the corresponding actual owner's publication scope. It cannot
authorize, delay, roll back, or retry publication. Source and replay cursor
publication stay inside the original neural generation, not a second journal
authority.

Diagnostic sampling, serialization, journal, or lease-release failure cannot
turn an applied/committed body into a retry. Summary rows are bounded by
declared phase/work kinds, admitted explicitly, and released; resource metadata
is charged before retention. Summaries retain no source text or generated
answer, and distinguish all observed publications from the request owner's
publications.

## Verification boundary

New `test_outer_learning_pipeline.py` cases use inert clocks/budgets,
AST-extracted source seams, and tiny real SQLite mutations. They cover nested
media/replay/publication once-only effects, exact current selected execution,
actual aggregate-selector consumption, stale/copied/foreign association
refusal, real admission and Stop, publication after an applied update,
isolated-candidate cancellation, private-effect refusal, and diagnostic failure.
They do not construct/load a brain, import Torch, run neural forward/backward,
train, create an evolution candidate, access a provider, or benchmark hardware.

This implements actual outer owner-phase orchestration and current prepared-
wave route consumption. It does **not** claim private qualification or relocation
of an entire mutable modality/replay/evolution pipeline, concurrent/cross-rank
execution, measured speedup, learned quality, or packaged-device evidence.
Phases without a real private closure remain explicitly owner-pinned. The
user-deferred trained-capability and full-folder proof remain deferred.
