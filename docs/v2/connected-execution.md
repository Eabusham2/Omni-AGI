# Exact inherited native execution

This is continuation of the original parent computation inside its retained
registered region, not an independent parent chat loop or a new target sampler.
An ancestral cursor cannot be passed directly to the larger connected decoder:
its KV geometry, action space and stochastic frontier belong to its original
native owner.

The user deferred the current-format inherited host/Worker integration proof
on October 13. It is not a current-goal test requirement and has not passed.
No replacement microfixture or neural execution is scheduled. The following
implementation and historical evidence remain preserved without turning that
deferral into a capability claim.

## Implemented boundary

- `connected_execution.py` adopts checked schema-2 execution checkpoints into
  a deterministic root queue. Active computation participates in region dedup
  identity; different suspended frontiers cannot accidentally share one region.
- `BorrowedRegionalOwner` uses the exact already registered decoder, memory
  bridge, idea adapter, router, liquid and modality objects. It never calls the
  neural constructor, clones learned weights, imports another model, or creates
  floating learned master weights. Only owner metadata and private writable
  runtime SQLite are copied. Immutable safe tensors can share storage.
- The original source IDs, token/cache/UTF-8 frontier, diagnostic before-image,
  native action ledger, observation receipts, global RNG and backend remain
  exact. Mixed per-module training flags, context geometry and outer root RNG
  are restored when the borrowed session exits, including failure.
- The root holds joint chat/training/evolution/observation mutations while
  inherited frontiers are queued. Each frontier drains in durable order. Source
  decoding does not re-admit its human message or commit a reply prematurely.
- Source finalization runs the real `AdaptiveBrain` implementation. Root-owned
  history, counters, latent replay, workspace/lifecycle activity, queued slow
  learning and a final receipt are adopted once. An already adopted human row
  is not rewritten; `inheritedInputAlias` binds its original turn/epoch/hash.
- New external actions use deterministic root-scoped 32-hex effect IDs and the
  new instance's permissions. Prior emitted actions remain suppressed. New
  evidence aliases preserve external execution/event IDs, payload hashes and
  completion times; an alias does not execute the effect again. Late results
  retain route aliases across re-suspension. Original neural argument views
  stay available through the trusted active-session owner; outward structural
  ID views are republished with checked root headers, not edited in place.
- Re-suspension stores another exact schema-2 frontier under a private
  root-owned runtime engine. Final result/Stop receipts are checksummed.
  A lost final acknowledgement returns the existing result with no tokens or
  actions emitted again. Stop is metadata/history-only, including when unloaded;
  it preserves actual partial output and the input without inventing learning.
- The regional owner has its own persisted activity clock, never the root's
  shallow-copied clock. Only active compute advances it; Unload wall time does
  not age activity. Re-suspension atomically publishes its paused clock into the
  new private runtime before cursor sealing, while checking the unchanged
  learned-generation binding. Native snapshots without the current clock and
  hardware/kernel compatibility seals are unsupported; they are not stamped
  with invented stochastic or timing state.
- `current()` remains an authenticated archival read, so old unsanitized
  snapshots and explicit Stop are not destroyed by newer runtime requirements.
  NEW adoption and executable file verification additionally call
  `require_supported_frontier`: a real supported runtime seal and a closed
  paused payload clock matching that source owner's metadata are mandatory.
- Every prepared view uses a new private runtime directory. Finalization never
  modifies the previously sealed suspension's replay/working/conversation
  files. Six-file runtime seals and the exact cursor inventory remain portable.
  Frozen source SQLite opens immutable/read-only and refuses a nonempty WAL or
  journal; even source SHM lock-table side effects are avoided.
- Late tool outcomes can be durably staged after a cursor freezes but before
  Unload releases the owner. `stage_inherited_observations` copies the exact
  frontier to another owned runtime, aliases the root receipt into the original
  source inbox, and atomically updates queue metadata without decoding a cache,
  loading another model, or changing neural weights. Duplicate receipt retries
  keep the same runtime pointer.
- Snapshot closure generators enumerate checked files and engine-local aliases,
  not arbitrary repository trees. Original regional identities/cache bindings
  remain untouched when the outer root is copied. Physical storage and RAM
  reservations remain real costs.
- Cold working-page updates/removals and overflow use a protected SQLite
  beforeimage until the root metadata commits. A cold-load helper restores it
  only for the unchanged old root; a valid completed root retains the new pages.
  Unfinished publication is not exported as if it were a coherent snapshot.

## Publication ordering

The first actual inherited fixture found a real self-lock: the outer regional
rollback transaction held `BEGIN IMMEDIATE` while `DirtyShardPlan` tried to open
the same cache for immutable graph publication. `prepare_publication()` now
releases/commits the derived-cache writer transactions before staging the root,
while keeping packed/control before-images alive. The atomic root metadata is
still the sole durable generation authority. A failed staging operation restores
learned bytes and requires cold recovery, which rebuilds derived caches from the
previous committed graph; it may not continue from a half-published warm view.
