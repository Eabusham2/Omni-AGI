# Actual reply-level placement consumer

This source slice composes the thirteen already supported complete native
operations into the real reply path. It does not create a fourteenth work
kind, a new model, a hidden prompt, a second learned weight copy or a measured
whole-reply speed claim. Full training and learned-capability qualification
remain deferred as requested.

## Real execution, not a summary-only wrapper

`reply_execution_planner.py` is composed into `AdaptiveBrain.chat` and the
actual sampling frontier in `OmniDecoder._generate_scoped_iter`:

1. The original serialized Worker request owns the live path. The existing
   initial routing forward uses its complete uncached-forward consumer.
2. Actual language/internal action heads, structured route/argument decoding,
   model-selected voluntary Ponder, its optional same-head self-report and
   branch-aware action materialization execute once on their current owner.
   The planner performs resource admission and accounts for their actual
   fixed-owner cost through the common whole-path scheduler. It does not force
   Ponder, change the learned action, or replay an argument/tool decision.
3. At each actual generation frontier the planner dispatches to the compatible
   existing consumer: a valid retained cache uses the complete retained-step
   consumer; an initial or naturally invalidated cache uses the complete
   first/refill-prefix consumer. Existing native closure, source, sampler,
   output/activity equality, ownership and admission checks remain authoritative.
4. Those consumers select placement using their real complete-operation
   observations plus this request's already observed pinned-owner cost, not
   primitive kernel timings or a previous reply's receipt. Transfer costs,
   all participating device budgets, current context, physical unified-memory
   groups and storage opt-in retain their existing checks. Mixed candidates
   must pass the separate exact mixed-route validator; this planner does not
   assume one base execution device or authorize an arbitrary mixed schedule.
5. Explicit `use_cache=False` preserves the existing full-forward arithmetic
   and home sampler. It is never silently exchanged for different cached
   reductions. Private Best Work branches, resumed/unknown schedules, changed
   owners/policies and missing concrete control custody keep their ordinary
   computation. A manually armed one-shot consumer retains its own review.
6. Actual stream, action, live-observation, activity, wait-for-evidence,
   control and suspension callbacks remain at their original once-only
   boundaries. They are not run during private trials. Finalization and its
   actual learning/checkpoint effects remain pinned, admitted and once-only.

The dispatch is an execution decision: the chosen existing complete consumer
actually supplies the current neural result/sample. It is not a later label
or receipt used to imply that another route ran. The sampler, token boundaries,
natural EOS/evidence waiting, cache invalidation, action ledger, steering,
continuation custody and stream order are unchanged. No global/process RNG is
reset or reseeded by the planner.

## Private qualification and real world boundaries

`world_effect_barrier()` refuses entry from a private operation before invoking
the callback and forbids recursive qualification while a real callback runs.
All six native policy entry points and the existing one-shot consumer honor
that gate. Callable-object protocols are retained, including inbox waiting and
suspension methods. A real exception after a callback's effect is propagated;
it never retries the callback or sends another actual tool request.

The real Worker `_chat` seam binds a runtime-only `ReplyControlFlags` namespace
to the exact brain, request path, turn, steering-session object and existing
cancel/steer/suspension `threading.Event` identities. Private comparisons read
those Events, not opaque user callbacks that may publish or mutate state. An
owner/session/Event replacement, Stop, Steer or Unload retires qualification.
The original callback still runs at its ordinary safe boundary. The exact
namespace alone is retired in `finally`; real Events are never cleared/reset
by this code. Unsupported controls do not gain authority from imported state.

`owned_operation_choice()` binds the prepared identity and actual selected
candidate at real consumer delivery/commit, after the existing native checks.
It can be observed only within the current live request. It neither authorizes
placement nor trusts saved JSON. Entered, completed and aborted delivery counts
are distinct; a stopped real sampling boundary is not a completed sample. The
outer learner uses this same narrow association around its genuine canonical
update, rather than treating a selection proposal as execution.

Actual heads, Ponder/router state, graph/SQLite, working/scratch/lasting memory
and world publications cannot all be privately migrated as one atomic object.
They remain on their real owners and are explicitly accounted for. No source
rollback or replay of real learning is disguised as an isolated comparison.
Diagnostic failure cannot repeat a committed body. Scoped counters and hashes
do not pretend to inventory facts or expose hidden chain-of-thought.

## Focused evidence

Sixteen distinct new cases in `engine/tests/test_reply_execution_planner.py`
passed across affected selections. They import stdlib-only modules under an
isolated test package, use inert metadata/clocks/callbacks, actual Events and a
tiny real SQLite effect ledger, and inspect the actual chat/generation/Worker
seams as AST/source. Coverage includes:

- real prefix/retained/refill dispatch and unchanged explicit uncached mode;
- actual complete-operation selector consumption, admitted fixed-owner cost
  and the resulting real callback/delivery association;
- pinned action/argument/Ponder/final learning phases without repeated writes;
- original callback protocols, failures after effects and scope unwinding;
- direct actual entry guards for perception, cached, prefix, forward, media
  and one-shot policy methods before any source/tensor/lock is accessed;
- exact current Event/request/turn custody, replacement, retirement and private
  Stop without an opaque callback poll;
- stale, missing, unknown, resumed and foreign-owner ordinary fallbacks;
- aborted/failed delivery versus completed operation accounting.
- publication after an already applied update, without adding another Stop or
  diagnostic pressure gate ahead of the original atomic save.

The clock values exercise the selector contract; they are not neural or
hardware speed evidence. No model/brain/decoder constructor, Load, neural
forward/backward, training, hardware benchmark or CI dispatch ran. Closed
operation and host suites were not repeated. Changed Python sources compile.

## Remaining implementation versus qualification

This implements the previously missing *ordinary real reply orchestration*
consumer, including fixed owner phases and once-only external boundaries. It
does not privately compare a complete conversation with repeated world I/O or
claim an optimal global schedule from per-operation measurements. Real
whole-reply latency/pressure and learned behavior remain missing evidence, not
another request to build/train a brain now.

The separately implemented mixed sequential consumer now covers six text kinds
only, and outer media/replay/evolution learning orchestration now accounts for
actual pinned phases and once-only publication. See
mixed-region-complete-operations.md and outer-learning-pipeline.md. These are
not concurrent execution or private migration of an entire mutable pipeline.
R1 breadth still needing compatible source includes concurrent/cross-rank
execution and collective custody, retained device-cache/context subtree
migration, unsupported direct accelerators and mixed consumers outside those
six text kinds where such routes are supported. Native equality, ownership and
resource gates remain unchanged; complete hardware/quality evidence is separate.
