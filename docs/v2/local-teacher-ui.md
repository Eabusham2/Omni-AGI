# Local teacher controls in Learn

The optional local-GGUF teacher section is mounted inside the existing Learn
workspace. It uses `omni.localTeacher`, not the API-teacher/provider controls,
and does not replace OmniCortex with a foreign model.

Choose an installed supported runtime and GGUF through main-owned file
selection. Visible hash preparation can be stopped. llama-server is the
preferred structured-completion route; explicitly chosen console runners keep
their transport framing and are labelled teacher-console data. Displayed
license declarations are not independently verified training permissions.

Prepare teacher fit uses the main-produced recommendation and measurements.
Unknown/blocked geometry never produces invented defaults or an enabled Start.
Generation fields are optional expanded technical settings, not personality
instructions. Their native/host memory accounting is checked again at Start.
Timeout0 means no wall-clock deadline, not an ETA or an exemption from Stop and
resource monitoring. Complete lesson prompts are separated by a line `---`;
multiline code/paragraphs remain in one lesson rather than Q/A lookup slots.

Generated lessons and native learned-source receipts have separate counters.
Neither count establishes truth, retention or comprehension. Job history has
Pause/Resume and an explicit Stop confirmation. Stop keeps generated data,
committed learning and source cursors. Copied dormant jobs have no working
Resume button: a new reviewed job/selection is required on the current host.
Lesson/source receipts are explicitly paged and shown on demand.

Creation retries preserve the exact request after an uncertain acknowledgement.
Instance changes reset local controls and fence late responses. Metadata/event
reads do not silently Load a brain, start a teacher or copy host grants.

## Focused evidence

Four new presentation cases passed in45ms: complete multiline lessons,
plan-setting round trip including timeout0, invalid-envelope rejection,
owner/revision filtering and no effects/provider/key/fit claim on initial
markup. Renderer TypeScript passed at that source point. A later visual fix
added a real body layout wrapper; a later Stop fix uses the typed terminal
selection progress to distinguish expected cancellation from genuine errors.
Their visual affected paths were checked without repeating earlier model or
teacher fixture suites.

Computer use exercised the actual component with synthetic main responses:

1. `01-light-entry.jpg` is diagnostic: open-details children lacked the
   intended vertical spacing. A targeted body wrapper fixed it without changing
   the app's existing layout or theme system.
2. File preparation showed exact hashed-byte progress. Stop initially left a
   stale “Stopping” message; the affected path was corrected and checked once:
   controls reenabled and said preparation ended, with no teacher job started.
   Completed selection, multiline prompts and unknown fit then showed a
   disabled Start. Corrected narrow light view is
   `02-light-corrected-unknown-fit.jpg`.
3. Estimated fit used the mock main recommendation. A lost creation response
   retried the identical request, and the synthetic ledger showed one unique
   job with two complete lessons. Pause/Resume/confirmed Stop and expanded
   lesson receipts were inspected below the fold in narrow dark view:
   `03-dark-stopped-receipts.jpg`. Fixture counts/receipts do not represent
   generated or learned real examples.
4. Switching instances removed the old selection, prompts, fit and job view.
   Desktop dark entry remained readable:
   `04-dark-desktop-owner-isolation.jpg`.

Images are under `test-results/local-teacher-ui-manual/`. No actual user files,
