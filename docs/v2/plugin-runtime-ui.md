# Plugin module controls: bounded native UI audit

October 15, existing production components in an isolated Electron window with
explicitly synthetic catalog/transport. No module source, neural model, provider,
real host action, training or saved instance was executed or modified by this UI
check. The separate real owned-JavaScript boundary test is not this fixture.

## Changes and observed steps

1. **Inactive, light:** declared event/UI/tool scope and explicit Activate are
   readable. Importing a package alone does not activate a module.
2. **Active, light:** contributed button appears and exact Ask operands are
   shown with separate Deny/Approve controls. This initially exposed unnecessary
   full session/request IDs in the main flow.
3. **Narrow, scrolled lower:** panel content and approval controls fit, but the
   exact JSON initially needed horizontal scrolling. IDs and wrapping were fixed.
4. **Affected narrow recheck:** IDs are now under collapsed Session/Request
   details, status is plain, `1 event` is grammatical, and the full exact path
   wraps without truncation. Scriptless `about:srcdoc` result content is visible.
5. **Deny and contributed control, dark:** Deny removes the synthetic pending
   approval and reports denial; the contributed button then updates its supplied
   synthetic count. Native grouped buttons replace an incomplete ARIA menu.
6. **Stop, dark:** Stop removes the contributed button and panel and returns
   the module controls to explicit activation. This is renderer binding evidence,
   not proof that a production child OS process was released.

## Source and integration

`PluginRuntimeControls` is mounted in the existing Plugin Manager.
`PluginRuntimeContributionsProvider` wraps the existing selected-brain workspace
once; four known slots consume it without independent repeated queries. Defaults
produce no added controls/spacing. Provider failures appear once in Tools;
per-action failures stay at their slot. Synchronous owner/hash fences prevent
previous-brain styles, snapshots and source selections from showing on a new
owner before effects clear state.

Seven distinct new renderer/presentation cases passed across the scoped runs:
initial five, one owner-switch regression, one ID/JSON/menu polish case. Renderer
TypeScript passed. No closed unrelated suite was rerun for those changes.

## Limits

Window 1100×1000 logical pixels; the narrow content surface was 360px, not a
physical 360px app window. Production component styles and native scrolling were
used with fixture-only outer placement. This does not establish full-app overlay
stacking, every theme, every accessibility interaction, real module installation,
neural schema learning, portable archive behavior or platform/package acceptance.
The visible Approve control was inspected; the UI run exercised Deny, not a real
host approval/effect. Source/fake-host permission fixtures are separate evidence.
